## 一、系统是什么（30 秒了解）

- **前后端一体**：一个 8000 端口同时托管「网页页面 + 后台接口 + 上传附件」，浏览器打开一个地址就能用全部功能。
- **技术组成**：后端 Python（FastAPI），前端 Vue（Node.js 打包成静态文件），数据库默认 SQLite（单文件，零配置）。
- **便携设计**：数据库、附件、前端产物都在项目文件夹内，**复制整个文件夹即可整体搬家**。

## 二、环境要求：先装好这些


| 需要装什么       | 版本要求                     | 用途         | 是否必须        |
| ----------- | ------------------------ | ---------- | ----------- |
| **Python**  | 3.10+（推荐 3.11/3.12/3.13） | 运行后端       | ✅ 必须        |
| **Node.js** | 18+（含 npm）               | 构建前端页面     | ✅ 首次必须，之后可省 |
| **MySQL**   | 8.0+                     | 多用户并发协作数据库 | ⚠️ 可选，默认用不到 |
| **Docker Desktop** | 最新稳定版 | 一键容器化部署（替代 Python/Node 安装） | ⚠️ 可选，用 Docker 方式时才需要 |


> **重要**：这两个运行时是装在电脑系统上的（不是项目里的），**不会**跟着项目文件夹走。换电脑必须重新装。

### 安装后先验证（命令行执行）

```bash
# Windows（cmd / PowerShell）
python --version     # 显示 3.10+ 即可
node -v              # 显示 v18+ 即可
npm -v               # 显示 9+ 即可

# Linux / macOS
python3 --version
node -v
npm -v
```

- Windows 装 Python 时**务必勾选 "Add Python to PATH"**，否则命令行找不到 `python`。
- Linux（Ubuntu/Debian）装 Python 与 Node：

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip curl
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt install -y nodejs
```

## 三、启动方式总览


| 方式                                 | 适合场景       | 说明                       |
| ---------------------------------- | ---------- | ------------------------ |
| **一键脚本**（`start.bat` / `start.sh`） | 日常自用       | 自动建虚拟环境、装依赖、自检并构建前端、启动后端 |
| **手动启动**（本文推荐）                     | 给客户演示 / 排错 | 每一步自己控制，出问题能一眼看出卡在哪一步    |
| **Docker**（进入 docker/ 目录） | 部署 / 演示 / 换机器 | 无需装 Python/Node，一条命令构建启动，详见 docker/README.md |



### 3.1 Docker 部署（推荐：无需装 Python / Node / MySQL）

> 项目已封装好 Docker，所有部署文件集中在 `docker/` 目录。**先进入 docker/ 目录**，再敲一条命令：

```bash
cd docker
docker compose up -d --build   # 首次构建 + 启动（在线自动下载依赖）
```

- 启动后访问 http://localhost:8000（admin / admin123）
- 数据在项目根 `data/` 文件夹，备份只拷它
- 完整操作、可选 MySQL、FAQ 见 **`docker/README.md`**

> 与脚本/手动方式的区别：Docker 把 Python + 依赖 + 前端全打进镜像，目标电脑**不用装任何运行时**，只需装 Docker。
> 脚本虽然省事，但它把"装依赖、构建"都静默完成了——**一旦某一步失败（比如依赖没装全），它会带着残缺状态继续启动**，表面"起来了"、实际页面打不开（就是之前登录页 404 的那次）。所以**给客户演示请用手动方式**，逐条执行、每步验证。

## 四、手动启动（推荐，最可控）

### 4.1 换电脑 / 首次准备：先删掉这些文件

**这是最关键的一步。** 项目运行时会自动生成一批文件（叫"生成物"），它们**绑定了当前电脑**：虚拟环境记死了 Python 路径、node_modules 可能没装全、dist 可能是构建失败留下的残次品。**换电脑后不删直接启动，大概率起不来或页面 404**。

启动前按下面清单处理（在项目根目录执行）：


| 路径                                        | 是什么                  | 换电脑后怎么处理                  | 为什么                                        |
| ----------------------------------------- | -------------------- | ------------------------- | ------------------------------------------ |
| `.venv/`                                  | Python 虚拟环境（装好的后端依赖） | **必须删掉**                  | 绑定了原机器的 Python 绝对路径，直接拷过来一定坏               |
| `frontend/node_modules/`                  | 前端依赖包                | **必须删掉，重新装**              | 可能不完整（缺包）或带原机器平台相关文件                       |
| `frontend/dist/`                          | 前端打包产物               | **必须删掉，重新构建**             | 可能是构建失败留下的残缺文件，删了重建最干净                     |
| `frontend/vite.config.js.timestamp-*.mjs` | Vite 临时文件            | 可删（垃圾文件）                  | 每次构建自动生成，无作用                               |
| 各目录下的 `__pycache__/`                      | Python 缓存            | 可删                        | 自动再生成                                      |
| `data/linkoa.db`                       | **数据库 = 你的数据**       | ⚠️ **不是垃圾，是数据**           | 想保留数据就带着；想要干净演示环境就删掉（启动会自动重建空库 + admin 账号） |
| `data/uploads/`                        | 上传的附件 = 你的数据         | ⚠️ 同上                     | 想保留就带着；演示建议清空                              |
| `backend/.env`                            | 配置文件（含 AI Key）       | ⚠️ 带着可用；不带也能启动（AI 功能需重新配） | 里面存了 DeepSeek API Key，别传 GitHub            |


**一句话记法**：`.venv`、`node_modules`、`dist` 三个"生成物"必删重来；`linkoa.db`、`uploads`、`.env` 是"数据/配置"，想保留就带着，不删也不影响启动。

删除命令：

```bash
# Windows（在项目根目录执行）
rmdir /s /q .venv
rmdir /s /q frontend\node_modules
rmdir /s /q frontend\dist

# Linux / macOS（在项目根目录执行）
rm -rf .venv frontend/node_modules frontend/dist
```

### 4.2 首次安装（每台新机器做一次）

在**项目根目录**执行以下命令（Windows 用 cmd / PowerShell，Linux 用终端）：

**① 创建虚拟环境 + 安装后端依赖**

```bash
# Windows
python -m venv .venv
.venv\Scripts\python -m pip install -r backend\requirements.txt

# Linux / macOS
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
```

> 验证：命令不报红色 error、能正常结束即可。报错基本是 Python 版本不对或没连上网。

**② 构建前端（把 Vue 源码打包成 dist）**

```bash
# Windows
cd frontend
npm install
npm run build
cd ..

# Linux / macOS
cd frontend
npm install
npm run build
cd ..
```

> 验证：看到 `✓ built in xx s` 即成功。若报"failed to resolve import ..."，说明依赖没装全，重跑一次 `npm install` 再 build。

**③ 确认配置文件 `backend/.env`**

- 从 GitHub 下载的代码里**没有** `.env`（它被 `.gitignore` 排除了，防泄露密钥）。
- 需要时手动创建：`copy backend\.env.example backend\.env`（Windows）或 `cp backend/.env.example backend/.env`（Linux），然后按需修改。
- **不建 `.env` 也能启动**：系统会用内置默认值（SQLite 数据库 + 默认密钥）。只是 AI 助手需要 Key 才能用。

### 4.3 日常启动（以后每次）

装好一次之后，**每次启动只需要一条命令**（首次启动会自动建表 + 创建 admin 账号，无需任何手工 SQL）：

```bash
# Windows（先进入项目根目录，再进 backend）
cd backend
..\.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# Linux / macOS
cd backend
../.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

看到 `Uvicorn running on http://0.0.0.0:8000` 即启动成功。

浏览器访问 **[http://localhost:8000](http://localhost:8000)**（本机），或 **http://电脑IP:8000**（同一局域网的客户电脑）。

> `--host 0.0.0.0` 表示允许局域网其他电脑访问（给客户演示必须带这个参数）。停止服务：在该窗口按 `Ctrl + C`。

## 五、一键脚本启动（懒人方式）

项目根目录已提供启动脚本，会自动完成「建虚拟环境 → 装依赖 → 前端完整性自检/重建 → 启动后端」：


| 系统            | 脚本          | 用法                                   |
| ------------- | ----------- | ------------------------------------ |
| Windows       | `start.bat` | 双击，或命令行输入 `start.bat`                |
| Linux / macOS | `start.sh`  | 先 `chmod +x start.sh`，再 `./start.sh` |


停止服务：


| 系统            | 脚本         | 说明                      |
| ------------- | ---------- | ----------------------- |
| Windows       | `stop.bat` | 按端口 8000/5173 结束进程      |
| Linux / macOS | `stop.sh`  | 同上（依赖 `lsof` 或 `fuser`） |


> 脚本同样会做「dist 完整性自检」：dist 存在但残缺（比如构建失败留下的半成品）会自动识别并重新构建，避免出现登录页 404。

## 六、数据库：默认 SQLite，可选 MySQL

系统默认使用 **SQLite**，零配置、单文件（`data/linkoa.db`），复制文件夹就能带走。


| 数据库            | 适用场景           | 特点                            |
| -------------- | -------------- | ----------------------------- |
| **SQLite（默认）** | 单机 / 演示 / 单人使用 | 文件随项目走，复制即用，不用装任何东西           |
| **MySQL**      | 多用户并发协作        | 多人同时改节点/文件更稳定，但**需要先装 MySQL** |


### 什么时候才用 MySQL？

**只有"多个员工同时在线改数据"才需要**。给客户演示、单人使用、几台电脑看数据——用默认 SQLite 就完全够了，**不用装 MySQL**。

### 如果用 MySQL（可选）

1. 先在电脑上装好 **MySQL 8.0+**，并创建数据库：

```sql
CREATE DATABASE linkoa CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

1. 切换配置（在 `backend` 目录执行）：

```bash
python switch_db.py mysql
```

1. 重启后端生效。切回 SQLite：`python switch_db.py sqlite`

> MySQL 连接串默认是 `root:123456@localhost:3306/linkoa`，可用环境变量 `LINKOA_MYSQL_URL` 覆盖。切换数据库时两套库是独立的，需要同步数据请用 `backend/` 下的 `migrate_mysql_to_sqlite.py` / `migrate_sqlite_to_mysql.py`（详见 `docs/领客文创OA_V1_数据库互转与MySQL部署指南.md`）。

## 七、登录与初始账号

- 登录地址：`http://localhost:8000`
- 初始管理员：**账号 `admin`，密码 `admin123`**

## 八、各模块使用说明

### 1. 首页

- 顶部「创建项目」卡片，三种方式：
  - **从空白创建**：新建空项目
  - **从模板创建**：套用标准流程模板（预置「标准IP设计流程」8 阶段）
  - **从 JSON 导入**：预留（暂未开放）
- 下方展示最近 5 个项目，点击进入详情

### 2. 项目（列表 + 画布详情）

- **项目列表**：按名称/客户/状态筛选，新建项目、归档/取消归档、删除
- **项目画布**（核心页面）：
  - 左侧画布：拖拽节点、连线，顶部有「节点库」按钮（点开选节点类型加入画布，节点带图标直观可辨）
  - **快速连线**：从某个节点右侧圆点拖出连线，在空白处松开会弹出「选择要连接的节点」浮层，点选后自动创建节点并连好线
  - 右侧面板：选中节点后填写**表单**（文本/下拉/上传图像/链接）、管理**附件**；未选中节点时看项目概览/讨论/操作记录
  - 图像字段可上传 1 张图并点击放大查看；链接字段填网址可点击跳转
  - 顶部「保存」按钮：保存当前选中节点的表单填写内容
  - 节点删除：点节点右上角 ✕，或选中后按键盘 Delete（都会二次确认）

### 3. 客户管理

- 左侧**客户单位** + 右侧**对接人**（分类=客户单位/公司，客户条目=该单位下的对接人）
- 增删改客户单位/对接人（删除有关联数据时会被拦截提示）
- **项目立项时**：选客户单位 → 多选该单位下的对接人（至少 1 人），项目卡片会同时显示「我方设计师 + 客户对接人」

### 4. 模板（流程模板）

- 「模板列表」是**纯流程编排**：只规定节点顺序和连线，不管表单
- 进入模板编辑页：从节点库选节点、连线、保存（整图提交）
- 表单字段统一在「节点模板」里维护（见下）

### 5. 节点模板（仅管理员，用户下拉菜单进入）

- 预设可复用的**节点类型**（如「立项登记」「需求对齐」等 8 个标准阶段）
- 每个节点模板可配置**表单字段**（单行文本 / 多行文本 / 下拉单选 / **上传图像** / **链接**）
- 可为节点模板设置**图标**（预设 20 个常用图标，或上传自定义图片）
- 项目画布和流程模板都从这里选节点类型，节点自动带出表单字段

### 6. 文件管理

- 左侧项目列表 + 右侧该项目的文件列表，点击左侧项目切换
- 支持搜索、上传（需选所属节点）、下载、删除
- **删除权限**：上传本人或管理员可删除任意文件

### 7. 消息中心

- 顶部铃铛显示未读红点
- 点击消息跳转到对应项目，自动标已读
- 「全部已读」按钮一键清空未读

### 8. 报表导出

- 按状态/客户单位/立项时间筛选，导出项目列表 Excel（仅管理员）

### 9. 用户管理（仅管理员）

- 用户卡片网格展示全部账号，支持按部门筛选
- **新建用户**：内部员工 = 选部门 + 分配角色（普通/管理员）；客户账号 = 选对接人（自动只读）
- 重置密码 / 启用停用 / 删除（不能删自己与 admin）
- **解锁账号**：账号锁定时卡片显示「已锁定」与「解锁」按钮
- **权限说明**：权限由账号上的角色决定——普通=能看数据+在项目里干活；管理员=全部权限

### 10. 部门管理（仅管理员，用户管理页「部门管理」按钮）

- 部门仅做人员组织分组，**不携带权限**
- 预置：研发部 / 设计部 / 市场部；部门下有用户时不可删除

### 11. 客户门户（客户账号）

- 客户登录后自动进入**独立门户**，只可查看**自己单位（公司）的全部项目**（只读）
- 顶栏展示公司名；支持项目名称搜索、进行中/已结项筛选、按立项时间范围筛选
- 项目卡片展示：倒计时（距截止）、客户单位、我方设计师、客户对接人、立项时间、预计结束时间
- 客户评价：项目「已归档」后出现「去评价」按钮，可查看三项评分与备注

### 12. AI 助手「青青侠」

- **常驻形象**：右下角公司吉祥物（呼吸浮动动画），悬停弹出随机气泡文案
- **对话能力**：接入 AI 大模型（默认 DeepSeek），流式输出，支持 Markdown、来源引用、停止生成、推荐问题
- **数据供给**：每次提问实时读库，把当前用户可见的全部项目渲染成文本注入大模型，只答系统内真实数据
- **数据隔离**：客户账号用 AI 只能问到所属公司的项目信息
- **管理配置**：管理员在「AI 设置」配置人设 prompt / 模型 / API Key / 接口地址 / 温度 / 最大 token
- 对话历史持久化，支持新建/切换/删除/置顶/重命名会话

> AI 首次使用前需管理员在「AI 设置」填好 API Key（或已在部署配置 `.env` 中预置），否则提示"AI 尚未配置 API Key"。

## 九、给客户演示前的检查清单

演示前按顺序过一遍，避免现场翻车：

1. **环境**：`python --version`、`node -v` 都正常（只手动启动后端的话，Node 只在构建时需要）。
2. **清理**：按 4.1 删掉 `.venv`、`node_modules`、`dist`（尤其是从别的电脑拷过来的文件夹）。
3. **装**：按 4.2 装后端依赖 + 构建前端。
4. **启动**：按 4.3 启动后端，确认看到 `Uvicorn running on http://0.0.0.0:8000`。
5. **验证**：浏览器打开 `http://localhost:8000` → 用 `admin / admin123` 登录 → 确认首页、项目画布、客户门户正常。
6. **客户访问**：同一局域网，客户电脑浏览器打开 `http://你的电脑IP:8000`（IP 用 `ipconfig`（Windows）/ `ip addr`（Linux）查看；防火墙需放行 8000 端口）。
7. **演示数据**：想要演示效果，先建好客户单位/对接人/项目/流程；想从零开始现场演示，就用干净库（删掉 `data/linkoa.db` 重启会自动重建）。

## 十、常见问题（FAQ）

**Q1：双击 start.bat 提示找不到 Python？**
先安装 Python 3.10+，安装时勾选 "Add Python to PATH"，然后重新打开命令行。

**Q2：换电脑后启动失败 / 登录页 404 / 白屏？**
90% 是"生成物"没清：按 4.1 删除 `.venv`、`frontend\node_modules`、`frontend\dist`，再按 4.2 重新安装和构建。特别是从别人电脑拷来的文件夹，这三样**必须删**。

**Q3：为什么 GitHub 下载的代码里没有 node_modules / dist / .env / 数据库？**
这些被 `.gitignore` 排除了（属于生成物和敏感配置），**故意不上传**。下载后必须按 4.2 在本机重新生成。

**Q4：怎么把数据从一台机器搬到另一台？**
复制整个项目文件夹即可（数据在 `data/linkoa.db`、附件在 `data/uploads/`）。目标机器装好 Python 3.10+，然后**删掉生成物**（`.venv`、`node_modules`、`dist`）重新生成，**保留** `linkoa.db`、`uploads`、`.env`。

**Q5：启动后登录报错 / 数据为空？**
确认 `backend/.env` 中 `DB_URL` 指向的数据库文件存在；若刚切换过数据库，可能需要先跑迁移脚本同步数据。

**Q6：多人同时操作感觉卡 / 数据冲突？**
切换到 MySQL（见「六、数据库」），多人并发写入更稳定。

**Q7：附件存哪了？**
`data/uploads/` 目录，按日期分子目录，文件名带 UUID 防重名。

**Q8：给客户演示，客户电脑打不开？**
确认 ① 后端用 `--host 0.0.0.0` 启动；② 两台电脑在同一局域网；③ Windows 防火墙放行 8000 端口；④ 客户浏览器访问的是 `http://你的电脑IP:8000`，不是 localhost。

**Q9：git 拉取/克隆后部署 Docker 报错、start.sh 在 Linux/macOS 打不开，但下载 ZIP 却正常？**
这是**换行符（CRLF/LF）问题**（就是之前说的"符号问题"）：`.sh` 入口脚本在 `core.autocrlf=true` 的 Windows 上被 git 检出成 CRLF，容器/Linux 里 shebang 变成 `#!/bin/sh\r`，于是报 `exec format error` / `no such file or directory`；而 GitHub 下载的 ZIP 是原始 LF，所以正常。
项目根目录已加入 **`.gitattributes`** 强制 `*.sh` 一律 LF、`*.bat` 保持 CRLF。处理方式：
- **本机更新**：直接 git pull 即可。若该机器此前已 clone 过、且 docker compose up 仍报"入口脚本 no such file or directory"，说明磁盘上的 .sh 还是旧 CRLF（Git 可能因"干净过滤器"跳过重写），执行下面两行强制落盘为 LF：
  ```
  del start.sh docker\docker-entrypoint.sh
  git checkout -- start.sh docker\docker-entrypoint.sh
  ```
  注：Dockerfile 已内置 sed 去除行尾 CR 的兜底，即使构建上下文是 CRLF 也会自动修复。
- **其他机器**：重新 `git clone` 或 `git pull` 即可，无需手动改文件。
- 换机器后**必须删掉生成物**（`.venv`、`node_modules`、`dist`）再运行 `start.bat`/`start.sh` 重新生成，详见 Q2。
