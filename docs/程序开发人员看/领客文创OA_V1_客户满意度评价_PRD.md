## 1. 产品目标

在项目归档后，让客户通过客户门户对自己的项目一次性提交「设计满意度 / 服务响应速度 / 最终产品」三项五星评分与选填备注，作为公司对交付质量的客户反馈依据；同时让内部员工在项目详情页看到该评价并撰写客户不可见的复盘反思，最终把评价与反思纳入报表导出，帮助老板/管理员掌握客户满意度与团队复盘情况，形成「交付 → 评价 → 复盘 → 沉淀」的闭环。

---

## 2. 用户故事

- **客户**：作为客户单位的账号，我希望项目「已归档」后在「我的项目」卡片上出现「去评价」按钮，点击后为设计满意度、服务响应速度、最终产品三项打 1~5 星并填写备注，一次性提交锁定，这样我能正式反馈满意度，且提交后同单位的其他同事只能查看、不会重复评价。
- **设计师 / 项目负责人**：作为内部员工，我希望在项目列表卡片看到「暂未评价 / 查看评价」状态、在项目详情页看到客户的三项评分与备注，这样我能第一时间了解客户对设计、服务和成品的真实反馈；并能在评价区块下方写一条客户永远不可见的反思/总结，这样团队能沉淀经验、改进后续项目。
- **管理员 / 老板**：作为管理员/老板，我希望客户提交评价后自动收到消息提醒，并在项目报表导出中看到三项评分、客户备注、评价时间与反思/总结（未评价留空），这样我能全面掌握客户满意度与团队复盘情况，用于考核和经营决策。

## 3. 需求池（P0/P1/P2 分级）

### P0（本次必须交付，核心闭环）

- **P0-1 数据表**：新增 `project_evaluation` 表，`project_id` 唯一（一个项目一条评价），字段见第 5 节。
- **P0-2 客户评价入口**：项目「已归档」后，客户门户「我的项目」卡片出现「去评价」按钮（仅已归档显示；进行中/取消归档后隐藏）。
- **P0-3 客户评价弹窗**：点击「去评价」弹出评价弹窗，三项打分文案用简称——**设计满意度 / 服务响应速度 / 最终产品**，每项 5 星（1~5 星），**三项必填**；备注为 1 个多行文本框，**选填**。
- **P0-4 一次性提交锁定**：客户提交后**一次性锁定**，提交后不能修改（不提供修改入口，后端拒绝二次提交）。
- **P0-5 单位级唯一评价**：一个项目一条评价，客户单位内任意一个账号提交后即锁定；同单位其他账号只能查看、不能重复评价。
- **P0-6 客户侧结果展示**：评价提交后，客户卡片由「去评价」变为「已评价」+「查看评论」按钮，点击弹出弹窗查看三项评分 + 备注 + 评价时间（只读；V1.4.17 改版：不再把评分直接平铺在卡片上）。
- **P0-7 内部列表状态**：内部项目列表卡片——已归档但客户未评价 → 显示「暂未评价」；已评价 → 出现「查看评价」按钮。
- **P0-8 内部查看评价弹窗**：点击「查看评价」弹窗展示客户三项星星 + 备注（+ 评价时间）。
- **P0-9 详情页评价区块**：项目详情页新增「客户评价」区块（三项星星 + 备注 + 评价时间）。
- **P0-10 反思/总结模块**：客户评价完成后，内部员工在评价区块下方写复盘反思/总结——**单条可编辑、所有内部员工可写、客户永远不可见**。
- **P0-11 消息通知**：客户评价提交后，自动给「项目参与人 + 管理员」发消息提醒（复用 `message` 表 + 消息服务，新增消息类型）。
- **P0-12 报表导出扩展**：项目列表 Excel 在现有 7 列后追加 6 列：设计满意度、服务响应速度满意度、最终产品满意度、客户备注、评价时间、反思/总结（未评价留空）。

### P1（本次应交付，健壮性与醒目提醒）

- **P1-1 低分标红**：任一单项评分 ≤ 2 星时，在内部项目详情页「客户评价」区块将该分数用红色醒目显示。
- **P1-2 取消归档边界**：项目被「取消归档」变回「进行中」时，评价按钮隐藏，但已提交的评价内容仍保留在详情页可见（数据不因状态回退而丢失）。

### P2（后续迭代，可选）

- **P2-1 评价数据统计看板**：三项评分的分布/均值统计看板（注意：评价存储不打总分、不求平均，此统计仅作管理层分析视图，不改存储口径）。
- **P2-2 未评价催评提醒**：对已归档但长期未评价的客户单位，内部可手动触发/定时催评消息。
- **P2-3 评价导出筛选**：报表导出增加「是否已评价」等评价维度筛选条件。

## 4. 核心交互说明

### 4.1 客户评价弹窗（客户门户）

1. 客户登录门户，进入「我的项目」，数据按 `sys_user.category_id` 隔离。
2. 项目状态为「已归档」时，卡片出现「去评价」按钮；「进行中」无此按钮。
3. 点击「去评价」弹出评价弹窗：
   - 三项打分：设计满意度 / 服务响应速度 / 最终产品，每项 5 星可点选，三项均必填。
   - 备注：单个多行文本框，选填。
   - 提交按钮。
4. 客户提交 → 后端校验三项均填写且该项目无既有评价 → 落库 `project_evaluation`（`evaluate_user_id`、`evaluate_time`）→ 锁定。
5. 提交成功：
   - 客户卡片由「去评价」变为「已评价」+「查看评论」按钮；点击弹出评价详情弹窗（三项星星 + 备注 + 评价时间，只读；V1.4.17 改版，不直接平铺卡片）。
   - 同单位其他账号查看该项目时，仅显示「已评价」+「查看评论」按钮，无「去评价」入口。
6. 若该项目已有评价（本单位或其他同单位账号已提交），后端返回不可重复评价，前端不展示「去评价」。

### 4.2 内部查看评价（员工端项目列表 + 详情页）

1. 项目列表卡片：
   - 已归档且客户未评价 → 显示「暂未评价」。
   - 已评价 → 出现「查看评价」按钮。
2. 点击「查看评价」弹窗：展示三项星星、客户备注、评价时间（只读，无编辑入口）。
3. 项目详情页「客户评价」区块：展示三项星星、备注、评价时间；任一单项 ≤ 2 星时该分数红色高亮（P1-1）。

### 4.3 反思/总结（员工端详情页，客户不可见）

1. 客户评价提交后，内部项目详情页「客户评价」区块下方出现「反思/总结」区域。
2. 所有内部员工（非客户账号）均可编写；单条记录，可编辑（覆盖式保存，保存后更新 `reflection_user_id` / `reflection_time`）。
3. 客户永远不可见：客户门户接口返回及展示一律不包含反思/总结字段；内部与客户接口彻底隔离。
4. 反思/总结的可见与编辑与项目是否「取消归档」无关——只要评价存在，反思区域即在详情页保留。

### 4.4 消息通知（复用消息中心）

1. 触发事件：客户提交评价成功。
2. 新增消息类型 `evaluation_create`。
3. 接收人 = 项目参与人（项目创建人 + 项目所有关联设计师）+ 全部「管理员」角色账号（排除无意义的操作人自身——本场景操作人为客户，不影响内部接收人）。
4. 消息内容建议：「客户已对项目「{项目名}」提交满意度评价」，点击跳转对应项目详情页。

## 5. 数据字段设计（`project_evaluation` 表）

> 遵循全局数据库约定：`bigint` 主键自增、逻辑关联不建物理外键、时间字段 `create_time`/`update_time`。得分字段用小整数存储 1~5，不打总分、不求平均，三项原样存储。

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键自增 |
| project_id | bigint | 所属项目ID（project.id，唯一；一个项目一条评价） |
| design_score | smallint | 设计满意度 1~5（必填） |
| service_score | smallint | 服务响应速度满意度 1~5（必填） |
| product_score | smallint | 最终产品满意度 1~5（必填） |
| customer_remark | text | 客户备注（选填，可空） |
| evaluate_user_id | bigint | 评价人ID（sys_user.id，客户账号） |
| evaluate_time | datetime | 评价时间 |
| reflection | text | 反思/总结（内部可见，客户永远不可见，可空） |
| reflection_user_id | bigint | 反思编辑人ID（sys_user.id，内部员工，可空） |
| reflection_time | datetime | 反思编辑时间（可空） |
| create_time | datetime | 创建时间（默认 CURRENT_TIMESTAMP） |
| update_time | datetime | 更新时间（默认 CURRENT_TIMESTAMP ON UPDATE） |

**索引：**
- `uk_project_id` (project_id) **UNIQUE** —— 保证一个项目仅一条评价，配合后端唯一校验实现「一次性锁定 + 单位级唯一」。

**字段类型建议补充：**
- 三项得分建议 `smallint`（对应 SQLAlchemy `SmallInteger`），后端/前端双重校验取值范围 1~5。
- `customer_remark`、`reflection` 用 `text`（对应 `Text`）。
- 时间字段沿用全局约定 `datetime`。

## 6. 待确认问题

1. **反思/总结的可见与编辑范围**：需求定为「所有内部员工可写」，是否包含与项目无关的其他内部员工？还是仅限「项目参与人（创建人 + 关联设计师）+ 管理员」？（建议：写权限收窄为「参与人 + 管理员」，避免无关人员误改。）
2. **客户提交前的二次确认**：因提交后一次性锁定不可改，是否需要在弹窗提交前增加「提交后不可修改」的二次确认提示？（建议：增加轻量确认。）
3. **消息接收人「管理员」范围**：是否所有 `role=管理员` 的账号都接收评价通知？（建议：全部管理员，与现有消息机制一致按角色推送。）
4. **低分标红范围**：P1-1 标红是否同时应用于内部「查看评价」弹窗，还是仅项目详情页区块？（建议：详情页区块与弹窗同时标红，保持一致性。）
5. **Excel 得分单元格格式**：三项评分导出为数字（1~5，便于统计）还是星级字符串（如「★★★★☆」）？（建议：数字 1~5，未评价留空。）
