## 版本变更说明（V1.2 → V1.4）

> 以下为本项目相对 V1.2 的演进，AI 生成代码时以「当前行为」为准，本说明辅助理解差异。

### V1.3 变更（节点模板库 + 表单定义收口）

1. **新增「节点模板库」**：管理员预设可复用的节点类型（含节点名称、说明、建议表单字段）。项目画布与流程模板只能从节点模板库选类型新增节点，不再自由创建节点类型。
2. **表单定义统一收口到节点模板库**：节点表单字段结构在「节点模板」里维护；项目节点实例化时从节点模板值拷贝表单字段（含下拉选项冗余）。
3. **流程模板改为纯流程编排**：只规定节点顺序 + 连线，不再配置表单字段。
4. **用户支持物理删除**：管理员可删除用户（不能删自己、不能删初始 admin）；删除后历史数据保留 user_id、姓名兜底"已删除用户"。

### V1.4 变更（文件管理 + 布局 + 便携化）

1. **数据库默认 SQLite**（单文件，V1.4.18 起统一位于项目根 `data/linkoa.db`，本地与 Docker 共用，相对路径配置，随文件夹迁移；见启动指南），保留 MySQL 双支持可一键切换。
2. **整体布局改顶部主导航**（去掉侧边栏）：项目 / 客户 / 模板 / 文件 / 消息 / 报表 / 用户管理。
3. **新增系统首页**：中央「创建项目」卡片（从空白 / 从模板 / 从 JSON）+ 最近项目列表。
4. **新增「文件管理」页**：左项目列表 + 右该项目的文件列表，集中查看/上传/下载/删除。
5. **画布连线浮层**：从节点 handle 拖出、在空白处松开，弹出「选择要连接的节点」浮层，点选后在该位置创建节点并自动连线。
6. **附件删除权限放宽**：上传本人 **或管理员** 可删除任意文件。
7. **消息中心新增「全部已读」**。

## 1. 项目概述

青岛领客文化传播有限公司内部OA项目管理系统。
业务对象：IP文创设计制作项目。
标准业务流程：`立项登记 → 需求对齐 → IP设计输出 → 方案内部评审 → 打样制作 → 实物生产 → 验收 → 项目归档`。

### 系统目标

1. 项目流程画布可视化，节点可自由拖拽、连线；支持流程模板复用。
2. **节点表单字段在「节点模板库」由管理员预设；项目实例从节点模板拷贝表单、仅填写表单值，不可修改结构**。
3. 统一管理节点备注、节点表单、设计稿附件、项目评论。
4. 完整操作审计，便于内部追溯。
5. 基础报表导出。
6. 底层代码模型解耦，方便后续迭代扩展。

### 部署约束

- **仅内网运行，禁止公网暴露**
- 单端口部署：FastAPI 后端同时提供 API 和前端静态文件

### 重要业务规则

1. **`参与设计师`字段仅做溯源展示标记，不做权限控制条件**。所有设计师可以查看全部项目，并且可以修改全部项目画布节点；但是设计师不能修改项目顶层基础信息、不能新建项目、不能归档/删除项目。
2. **模板节点表单结构**：仅管理员/行政/设计总监在编辑模板时定义；设计师只能填写表单内容，不能增删改表单字段结构。
3. **使用模板新建项目**：节点、节点备注、表单字段定义、节点坐标、节点连线全部为值拷贝；新项目与模板彻底解绑，模板后续修改不会影响已经创建完成的历史项目。
4. **项目运行中临时新增节点**：仅具备基础功能（节点标题+节点备注+附件上传+评论），不带自定义表单字段，严格保证"表单结构仅在模板阶段定义"。

## 4. 账号用户模块

1. 只有管理员可以新建账号，角色可选：行政 / 设计总监 / 设计师。
2. 所有用户仅可以修改**自己的登录密码**。
3. 管理员：查看全部账号列表，界面直接展示用户明文密码；支持重置任意用户密码、启用/停用账号。
4. 行政、设计总监、设计师，无创建用户权限。
5. **用户不做物理删除**，仅支持启用/停用。已停用用户禁止登录，但依旧保留在历史项目参与人员，历史数据正常参与报表统计。
6. 初始管理员账号：`admin / admin123`。

## 5. 客户单位与对接人模块（V1.4.7 语义升级）

**两级结构**：客户单位（公司/机构）= 原「客户分类」表 `customer_category`；对接人（人）= 原「客户」表 `customer`，隶属某个客户单位。

- 客户单位字段：单位名称
- 对接人字段：对接人姓名、所属单位、备注（文字，记录职务、联系方式等）

### 权限规则

1. 管理员：新增、编辑、删除客户单位与对接人。
2. 其他内部角色：仅查看，不可编辑。

### 删除约束

1. **删除客户单位**：单位下存在对接人，或已被项目引用（`project.category_id`），返回 400 禁止删除。
2. **删除对接人**：该对接人被项目引用（`project.customer_id` 或 `project_contact_rel`），返回 400 禁止删除。

### 与项目的关系（V1.4.7）

1. 新建/编辑项目时先选**客户单位**，再多选该单位下的**客户对接人**（至少 1 人）。
2. 项目卡片与门户详情均展示「我方设计师（多人）+ 客户对接人（多人）」。
3. 客户门户账号绑定某个对接人，登录后可见该对接人所属**客户单位的全部项目**。

## 6. 流程模板模块

1. 管理员、行政、设计总监：可新增、编辑、删除流程模板；设计师仅可选用模板。
2. 模板包含数据：预设画布节点（含坐标）、节点连线、每个节点的节点备注；节点通过 `node_template_id` 关联节点模板（表单定义在节点模板库，不在流程模板里）。
3. **模板编辑采用自由拓扑画布**（与项目详情页复用同一套画布组件），管理员在画布上从节点模板库选节点、连线。
4. **模板保存机制 = 整图提交**：管理员配置完成后点击【保存模板】按钮，前端将整个画布的 nodes（含坐标与 nodeTemplateId）和 edges 一并提交，后端单事务全量覆盖更新。
5. 节点表单字段类型（单行 text_single / 多行 text_multi / 下拉 select）在「节点模板库」配置，流程模板不配置表单。
6. 使用模板新建项目：**值拷贝复制全部节点+节点坐标+节点连线+节点备注，实例化时根据 node_template_id 从节点模板拷贝表单字段定义，实例化后与模板彻底解绑**。模板后续修改删除，不影响已生成的历史项目。
7. 删除模板为物理删除（单事务内删除模板、节点、连线），删除动作写入操作日志。因深度解绑，删除模板不影响历史项目。

## 7. 项目核心模块

### 7.1 项目状态（仅两种）

1. **进行中**：新建项目默认为进行中；节点、备注、表单、附件、评论均可增删改。
2. **已归档**：全部内容只读；禁止节点、备注、表单、附件、评论增删改；管理员/行政/设计总监可以取消归档回到进行中。

### 7.2 项目顶层基础信息（仅管理员、行政、设计总监可编辑）

- 项目名称
- 客户单位（下拉选择；V1.4.7 由原「关联客户」升级）
- 客户对接人（多选，只能选该单位下的对接人，至少 1 人；V1.4.7 新增）
- 项目描述
- 预计结束时间（门户展示为「预计结束时间 / 距截止」）
- 参与设计师（多选人员，仅溯源展示，不做权限控制）

> 立项时间 = 项目创建时间（不可编辑）。

### 7.3 项目删除逻辑

项目删除执行**物理删除**：项目、节点、节点连线、节点备注、节点表单填写数据、附件、评论、项目-设计师关联、项目相关消息全部业务数据销毁；服务器本地磁盘上的附件文件同步删除。
- 仅操作审计日志永久留存删除记录，删除之后项目不可恢复。
- 删除权限：管理员、行政、设计总监。
- **已归档项目必须先取消归档才能删除**，后端返回 400，提示"已归档项目请先取消归档后再删除"。

## 8. 画布节点与节点自定义表单

### 8.1 画布基础规则

1. 节点为独立实体，模板复制是值拷贝，节点之间无引用关系。
2. **全部角色（管理员/行政/设计总监/设计师）都可以对任意项目的节点做新增、修改、删除**。
3. 每个节点内置**节点备注文本框**，所有角色均可编辑；项目归档之后节点备注不可编辑。
4. 节点画布坐标使用 `decimal(10,2)` 存储（pos_x, pos_y），支持浮点数，避免缩放拖拽后重绘抖动。
5. 节点之间支持连线（自由拓扑），连线可带文字标签（label，可空）。
6. **删除节点时，后端在同一事务内自动级联物理删除以该节点为 source 或 target 的全部出入连线**，避免孤儿连线导致前端渲染报错。

### 8.2 节点自定义表单

- 表单字段结构在「节点模板库」由管理员配置。
- 项目实例中：所有角色可填写、修改表单值；**所有人不能修改表单字段结构**。
- 冗余保存表单字段名称、类型、下拉选项，避免节点模板修改破坏历史项目数据。
- 项目节点表单字段**从节点模板 form_fields 值拷贝**（项目运行中新增节点同样带表单）。

### 8.3 并发与交互

1. V1 无协同编辑锁；多人同时编辑同一个节点，后保存直接覆盖先保存；两次修改完整记录操作日志。协同锁放到后续迭代。
2. **拖拽坐标批量提交**：前端拖拽节点结束后做防抖处理，调用批量更新坐标接口 `/api/projectNode/batchUpdatePositions`（入参 `[{id, posX, posY}]`），避免高频单条请求导致并发覆盖。
3. 删除节点物理销毁节点、节点备注、节点表单填写数据、节点连线；删除行为写入操作日志。
4. 项目归档状态：节点、节点备注、节点表单全部不可增删改，画布设置 `nodesDraggable="false" nodesConnectable="false"`。

## 10. 附件管理

1. 所有角色都可以在项目节点上传附件。
2. **附件上传人 或 管理员可删除附件**，删除附件写入操作日志。非上传本人且非管理员删除返回 403。
3. 项目归档状态：禁止上传、禁止删除附件。
4. **文件存储**：保存在公司服务器本地磁盘，路径格式 `uploads/YYYYMMDD/UUID_原始文件名`（日期隔离 + UUID 防重名）。
5. **单文件最大 1G**。
6. **允许任意常见格式**：图片、文档、设计稿（.psd/.ai）、压缩包（.zip/.rar）等；管理员可设置黑白名单（V1 先不做管理界面，代码预留配置项）。
7. 第三方对象存储放到后续迭代。
8. 删除项目时，服务器本地磁盘上的附件文件同步删除。
9. 删除节点时，节点下的附件不自动删除（保留在项目中，project_node_id 变为无效值，前端不再展示）。

## 11. 评论管理

1. 全部角色可以在项目下发表评论（项目级，非节点级）。
2. 用户仅可删除自己发布的评论，删除写入操作日志。非本人删除返回 403。
3. 项目归档状态：禁止新增评论、禁止删除评论。
4. 评论列表按时间倒序展示，显示评论人姓名、头像、时间、内容。

## 15. 鉴权与接口规范

### 15.1 鉴权方式

- 登录接口返回 JWT Token，前端存储在 localStorage
- 后续所有需登录接口，请求头携带 `Authorization: Bearer <token>`
- Token 过期时间：24 小时
- JWT 密钥从 `.env` 环境变量读取（`JWT_SECRET`）
- 后端校验失败返回 401

### 15.2 统一返回格式

```json
{
  "code": 200,
  "msg": "",
  "data": {}
}
```

### 15.3 错误码

| code | 含义 | 触发场景 |
|---|---|---|
| 200 | 成功 | 正常返回 |
| 400 | 参数错误 / 业务规则不满足 | 归档项目禁止操作、删除别人附件、参数缺失、删除约束拦截 |
| 401 | 未登录 / token 失效 | 无 token、token 过期、签名错误 |
| 403 | 无权限 | 角色不允许调用该接口 |
| 500 | 服务器内部错误 | 异常未捕获 |

### 15.4 分页规范

- 请求参数：`pageNum`（默认1）、`pageSize`（默认10）
- 返回结构：`{items, total, pageNum, pageSize}`
- 分页接口：项目列表、客户列表、全局审计日志、个人消息列表
- 不分页接口：用户列表、客户分类列表、模板列表、项目内日志、节点附件、项目评论

### 15.5 数据库全局约定

- 字符集：`utf8mb4`，排序规则 `utf8mb4_unicode_ci`
- 引擎：`InnoDB`
- 不建物理外键，纯逻辑关联，级联由后端代码事务控制
- 主键：bigint 自增
- 时间字段：create_time 默认 CURRENT_TIMESTAMP，update_time 默认 CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
- 业务表均物理删除，不设软删除字段

## 18. AI 助手模块（V1.4.8 新增）

### 18.1 功能概述

常驻 AI 助手「青青侠」（公司 IP 吉祥物形象），供内部员工与客户门户客户使用。右下角浮动形象 → 点击展开对话弹窗，接入大模型（默认 DeepSeek）做流式问答，并注入结构化项目知识库（全量项目文本），帮助员工/客户快速了解项目进度、客户信息、流程节点等业务问题，也支持日常闲聊。

### 18.2 交互设计

1. **常驻形象**：屏幕右下角固定显示「青青侠」形象，呼吸浮动动画。
2. **悬停交互**：鼠标悬停形象轻微摇头放大，弹出**随机气泡文案**（问候语，纯前端配置数组）。
3. **点击展开**：点击形象平滑过渡为**居中弹窗**（桌面约占屏幕 2/3，移动端全屏），形象淡出、弹窗头部显示缩小头像，动画自然衔接。
4. **对话能力**：流式打字机输出；支持 Markdown 排版、**来源引用**、**停止生成**、**推荐问题**快捷提问。
5. **对话历史**：左侧会话列表（仿豆包/DeepSeek），可新建/切换/删除，历史持久化。

### 18.3 数据隔离（安全红线）

- **员工账号**：可访问全量项目数据。
- **客户账号**：结构化知识库构建时强制按 `Project.category_id == 所属客户单位` 过滤，**只能问到本公司的项目信息，绝不泄露其他公司的任何数据**。

### 18.4 可扩展架构（多模型）

- 后端 `services/llm/` 定义 `BaseLLMProvider.stream_chat` 抽象基类 + `DeepSeekProvider`（OpenAI 兼容流式）+ `get_provider(config)` 工厂；未来接入更多模型只需新增 Provider 实现类，不改业务编排。

### 18.5 管理员配置

- 管理员在用户下拉「AI 设置」页配置：人设 prompt、模型名称、API Key、接口地址（Base URL）、温度、最大 token；API Key 脱敏展示（含 `****` 表示沿用旧值不修改）。

### 18.6 数据表

- 新增 `ai_config`（AI 全局配置，单行）、`ai_conversation`（会话，按用户隔离）、`ai_message`（消息，role/content/sources）三张表，详见 Database.md。
