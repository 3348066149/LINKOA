====================================================================
  LINKOA 领客文创 OA · 离线部署说明
====================================================================
适用场景：目标机器（如公司 NAS / 无外网服务器）无法访问外网，
无法 docker pull 基础镜像时，用本离线包完成部署。

离线包文件：  docker/linkoa-latest.tar
镜像名称：    linkoa:latest
文件大小：    74,143,232 字节（约 70.7 MB）
MD5 校验值：  52e8d6afd96b3d3f5f8e4addc4b4d962
构建时间：    2026-09-04

--------------------------------------------------------------------
一、需要的文件
--------------------------------------------------------------------
方式 A（推荐，用 docker-compose，数据和配置最省心）：
  把整个项目目录 LINKOA/ 完整拷贝到目标机（至少包含以下内容）：
    docker/                  ← docker-compose.yml、本说明、离线包
    data/                    ← 数据目录（数据库 + 附件，可先建空目录）
  注意：目标机上只需要 docker/ 和 data/，不需要 backend/frontend
  源码，镜像已打进 tar 里。

方式 B（只用 docker run，只拷一个 tar 即可）：
  只需 linkoa-latest.tar 这一个文件。

--------------------------------------------------------------------
二、把离线包传到目标机（关键：必须传完整！）
--------------------------------------------------------------------
推荐用 scp 或 WinSCP 传输，不要用浏览器/网盘拖拽（容易截断）：

  # Windows 本机 PowerShell 里执行（link 换成目标机地址/账号）
  scp "E:\Docker\LINKOA\docker\linkoa-latest.tar" 账号@目标机:/目标目录/

传到目标机后，先校验文件是否完整，再继续（这一步不能省）：

  ls -l linkoa-latest.tar
  # 必须显示 74143232 字节；如果小于这个数 = 传坏了，重新传

  md5sum linkoa-latest.tar
  # 必须等于 52e8d6afd96b3d3f5f8e4addc4b4d962
  # 不一致 = 文件残缺，重新传（否则 docker load 会报 unexpected EOF）

--------------------------------------------------------------------
三、加载镜像
--------------------------------------------------------------------
  sudo docker load -i linkoa-latest.tar

成功会显示：
  Loaded image: linkoa:latest

验证镜像已存在：
  sudo docker images | grep linkoa

--------------------------------------------------------------------
四、启动（两种方式任选其一）
--------------------------------------------------------------------
▌方式 A：docker-compose（推荐）
  把整个项目（含 docker/ 和 data/）放在目标机，进入 docker/ 目录：

    cd /目标目录/LINKOA/docker
    docker compose up -d

  （镜像已 load，compose 直接用现成镜像，不要加 --build）

▌方式 B：docker run（只有 tar 时用）
  先建好数据目录，再运行：

    mkdir -p /目标目录/data
    sudo docker run -d \
      --name linkoa \
      --restart unless-stopped \
      -p 8000:8000 \
      -v /目标目录/data:/app/data \
      -e DB_URL="sqlite:////app/data/linkoa.db" \
      -e UPLOAD_DIR="/app/data/uploads" \
      -e JWT_SECRET="改成你自己的随机长字符串-至少32字节" \
      linkoa:latest

  （8000 如被占用，把 -p 8000:8000 改成 -p 8001:8000）

--------------------------------------------------------------------
五、验证部署成功
--------------------------------------------------------------------
  1) 看容器状态：
       docker ps            # 应看到 linkoa 容器 Up，STATUS 为 healthy
       docker logs -f linkoa   # 无报错，出现 uvicorn running 即正常
  2) 浏览器访问：
       http://目标机IP:8000
     初始账号：admin    密码：admin123
  3) 健康检查接口：
       curl http://目标机IP:8000/api/health   # 返回正常 JSON 即成功

--------------------------------------------------------------------
六、数据与备份
--------------------------------------------------------------------
  · 数据库：  data/linkoa.db
  · 附件：    data/uploads/
  · 备份：把整个 data/ 文件夹拷走即可，数据全在里面。
  · 迁移到新机器：新机器装 Docker → 拷 tar + data/ → 重新
    docker load → 按第四步启动，旧数据原样可用。

--------------------------------------------------------------------
七、可选配置（.env，仅 compose 方式）
--------------------------------------------------------------------
  在 docker/ 目录创建 .env 文件（与 docker-compose.yml 同级）：
    LINKOA_PORT=8000                    # 宿主机端口
    LINKOA_JWT_SECRET=你的随机密钥      # 生产必改，>=32 字节
    LINKOA_AI_API_KEY=sk-xxx            # AI 助手密钥（可选）
    LINKOA_AI_BASE_URL=https://api.deepseek.com
    LINKOA_AI_MODEL=deepseek-v4-flash
  改完执行： docker compose up -d  重启生效。

--------------------------------------------------------------------
八、常见问题（FAQ）
--------------------------------------------------------------------
Q1：docker load 报 "unexpected EOF"
  原因：tar 文件传输不完整或磁盘空间不足。
  处理：先看文件大小是否等于 74143232 字节、md5sum 是否等于
  52e8d6afd96b3d3f5f8e4addc4b4d962；不一致就重新完整传一次。
  一致仍报错则检查磁盘空间：df -h /目标分区。

Q2：docker load 报 "no space left"
  磁盘满了。docker load 解压需要至少 1GB 空闲，先清理或扩容。

Q3：compose 启动报 "build" 相关错误
  用 docker compose up -d 而不是带 --build；镜像已存在时无需构建。

Q4：启动后页面 404 / 白屏
  看日志 docker logs linkoa；多半是端口没映射对，或没访问对端口。

Q5：端口 8000 被占用
  compose 方式：.env 里改 LINKOA_PORT；
  docker run 方式：把 -p 8000:8000 改成其它端口。

Q6：想用 MySQL（多人并发才需要）
  离线环境额外加载 mysql:8.0 镜像（另行离线导出），
  再叠加 docker-compose.mysql.yml 启动。
