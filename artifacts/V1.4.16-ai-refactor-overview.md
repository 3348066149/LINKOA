# LINKOA V1.4.16 — AI 助手数据供给改造（交付概览）

## 一句话总结
把「青青侠」的数据供给方式从「中文关键词 + SQL LIKE 匹配 + 联网搜索」改为**结构化文本知识库全量注入**，并按公司名做客户隔离，回答准确性显著提升、彻底消除"用户表达不在关键词内就落空"的顽疾。

## 改造要点
| 维度 | 之前 | 现在 |
|------|------|------|
| 数据供给 | 关键词切分 + SQL LIKE 检索 | 每次提问实时读库，全部项目渲染成固定模板文本注入 system 层 |
| 联网搜索 | 输入框「联网搜索」开关（Responses API） | 移除，纯本地知识库问答 |
| 客户隔离 | RAG 检索按 category_id 过滤 | SQL 层 `WHERE category_id == 所属单位` 精确过滤 |
| 防幻觉 | 业务关键词命中 + 检索为空 → 短路 | 知识库为空 → 短路返回固定话术 |
| 注入字段 | 含进度%、当前节点等 | 仅项目名称/客户单位/对接人/我方负责人·设计师/立项时间/预计结束时间/项目状态（不含进度、当前节点） |

## 知识库模板（一项目一条）
```
项目【名称】｜客户单位：X｜对接人：A、B｜我方负责人/设计师：C、D｜立项时间：YYYY-MM-DD｜预计结束时间：YYYY-MM-DD｜项目状态：进行中/已结项
```

## 关键文件
- `backend/app/services/llm/retriever.py` — 重写为 `build_knowledge_base(db, current_user)`
- `backend/app/services/ai_service.py` — 全量注入编排 + 空库短路
- `backend/app/services/llm/deepseek.py` / `base.py` — 摘 `/responses` 与 `web_search`
- `backend/app/schemas/ai.py` / `routers/ai.py` — 摘 `web_search` 契约
- `frontend/src/components/ai/ChatInput.vue` / `ChatPanel.vue` / `stores/ai.js` / `api/ai.js` — 摘「联网搜索」开关
- `backend/tests/qa_retriever_verify.py` / `ai_full_check.py` / `mock_llm.py` — 测试同步
