## P0 修复：SPA 兜底误吞静态图片（logo 等显示破图）

**症状**：登录页 logo（`/link-icon.png`）显示为破图标；凡 dist 根目录下非 `/assets` 的文件（logo、ai-mascot 图等 public 静态资源）全部 404 回退 index.html。

**根因**：`main.py` 的 `FRONTEND_DIST = os.path.join(BASE_DIR, "..", "frontend", "dist")` **未规范化**（含 `..`），而 spa_fallback 防穿越检查用 `os.path.realpath(candidate)` 与**未规范化的 FRONTEND_DIST** 做 startswith 比较 → 永远 False → 所有 dist 根静态文件被误判为路径穿越，全回退 index.html（495 字节 text/html，curl 抓包实锤）。

**修复**：`FRONTEND_DIST = os.path.realpath(os.path.join(...))`（1 行）。`/assets` 与 `/uploads` 是直接 StaticFiles mount，不受影响，故封面/表单文件/节点图标一直正常。

**验证**：重启后 `/link-icon.png` 返回 30764 字节 PNG、`/ai-mascot/qingqingxia.png` 200 image/png、`/login` SPA 刷新 200、assets js 200；full_flow_check 92/92 通过。
**教训**：防穿越检查的基准路径与待检路径必须同用 realpath 规范化，否则 Windows 上含 `..` 的 join 结果必然误判。

## 修复：打包镜像.bat 报错（docker compose 命令不可用）

**症状**：运行 `打包镜像.bat` 报错，卡在第 1 步构建。

**根因**：本机 `docker compose`（空格形式，Compose V2 插件）不可识别——`docker: unknown command: docker compose`；但 `docker-compose`（连字符形式）**可用**（v2.40.3-desktop.1）。Docker Desktop 装了 cli-plugins 但空格形式未生效（PATH/插件识别问题），属环境差异，不应写死一种形式。

**修复**：脚本内加 compose 命令自动探测——先试 `docker compose version`，失败回退 `docker-compose version`，两者都无则提示装 Docker Desktop；探测结果存 `%DC%` 变量后续复用，并 echo 实际使用的命令便于排查。

**验证**（全程实跑）：
1. `docker-compose -f docker/docker-compose.yml build` → `linkoa:latest` 311MB 构建成功（全 CACHED）；
2. `docker save` → `docker/linkoa-latest.tar` 73MB 导出成功；
3. `scripts/server_start.sh` 已拷贝到 `docker/`；
4. 本地起 `linkoa-verify` 容器（映射 18000）→ `Up (healthy)`，`/api/health` 返 ok、`/linkoa-icon.png` 返 30764 字节 PNG（本次图片修复已随镜像生效）、`/api/login` 登录成功返 token、`/uploads/cover/*` 走卷挂载正常；验证后已 `docker rm -f`。
5. 复核 `.dockerignore` 已正确排除 `data`、`.env`、`.git`、`node_modules`——构建上下文干净，密钥与数据不会打进镜像。
