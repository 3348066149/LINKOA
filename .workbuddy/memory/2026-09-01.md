## 新增 Ubuntu/Linux 一键启动脚本 start.sh（夜 23:04）

- 用户要求 Ubuntu 一键启动。新建项目根 `start.sh`（bash），功能对齐 `start.bat`：cd 到脚本目录（相对路径规范）→ 建/重建 .venv（损坏则 rm 重建）→ pip install -r backend/requirements.txt → 若 frontend/dist 缺失且 node 存在则 npm install && build（失败仅告警不退出）→ cd backend && exec uvicorn app.main:app --host 0.0.0.0 --port 8000。`set -euo pipefail`，语法 `bash -n` 通过，文件已带 +x。
- 回填启动指南：恢复「Linux/macOS 用 start.sh」章节（chmod +x start.sh / ./start.sh），总述改"启动脚本（Windows start.bat / Linux start.sh）"，停止说明补 Linux 用 `pkill -f "uvicorn app.main"`；backend/README 也加一句 Linux/macOS 用 start.sh。至此文档与项目真正对应（此前指南因缺脚本临时改为"仅 Windows"）。
- 用户追加要求补 Linux 停止脚本。新建 `stop.sh`（bash），对齐 `stop.bat`：cd 脚本目录 → 按端口 8000/5173 查杀（lsof 优先，fuser 兜底）→ 兜底 pkill -f "uvicorn app.main"（TERM，1 秒后残留 -9 强杀）。`set -uo pipefail`（不 -e，pkill 未命中会非 0），语法 `bash -n` 通过，文件带 +x。
- 回填启动指南停止说明：改为对称（Windows stop.bat / Linux stop.sh，均按端口 8000/5173 + 兜底进程名结束）；backend/README 补"Linux/macOS 停止用 stop.sh"。至此 Ubuntu 一键启停与 Windows 完全对应。
- **start.sh 健壮性修复（Ubuntu 实测）**：用户实机跑报 `.venv/bin/python: No module named pip`——原脚本只检查 `python` 是否可执行，漏判 pip，遇到"有 python 无 pip"的坏 venv 就跳过重建立。改为 venv 健康检查 = python 可执行 **且** `python -m pip --version` 可用，否则删 `.venv` 重建；venv 创建失败或 ensurepip 退化时提示 `sudo apt-get install -y python3-venv python3-pip`。`bash -n` 通过。
- 依赖安装进度可见性：原 `pip install -q` 静默吞掉进度，去掉 `-q` 让终端实时显示下载/安装进度。
- **start.sh 路径 bug 修复（Ubuntu 实测）**：依赖装好启动时报 `backend/.venv/bin/python: 没有那个文件或目录`——根因 `$VENV_PY` 用相对路径 `.venv/bin/python`，而启动前 `cd backend` 把 cwd 切成后端目录，相对路径被错拼成 `backend/.venv/bin/python`。改为 `VENV_PY="$(pwd)/.venv/bin/python"` 绝对路径，`cd backend` 后仍指向项目根 `.venv`，根治。`bash -n` 通过。
